# AI와 함께 내 리서치 앱 고치기

에이전트가 보고서를 쓰는 방법은 앱의 **팀 구성**에서 고칠 수 있습니다. 차트의 동작이나 화면을 바꾸고 싶다면 소스 복사본을 Codex에 열어 수정하세요. 실습은 강사가 배포한 앱을 계속 쓸 수 있도록 별도 폴더에서 진행합니다.

## 화면이 막혔을 때 무엇을 알려줄까요?

시작한 메뉴, 입력한 종목과 데이터 출처, 누른 버튼, 화면에 실제로 나온 문구를 적으면 원인을 좁힐 수 있습니다. 화면을 첨부하기 전 API 키, App Secret, 계좌번호가 보이는 부분은 가리세요. 키는 본인 앱의 연결 창에 직접 입력합니다.

아래에서 대괄호 부분만 바꿔 AI에 보내세요.

```text
저는 Hyperpass를 처음 쓰고 있습니다. [Windows 또는 Mac]에서 [앱 버전]을 사용해요.
[차트 연구실]에서 [SK하이닉스]를 입력하고 데이터 출처를 [TradingView]로 바꿨습니다.
기대한 것은 [SK하이닉스일 때 오른쪽에도 새 차트 표시]입니다.
실제로 보이는 제목·출처·오류는 [화면 문구]입니다.
앱 화면에서 먼저 확인할 항목을 하나씩 안내해 주세요. 제 키나 계좌 정보를 요청하지 마세요.
```

## 역할과 분석 방법부터 바꿔보기

**역할 지침**은 담당자가 어떤 질문에 답하고 무엇을 넘겨줄지 정합니다. **분석 방법**은 근거를 살펴볼 순서와 결과의 형식을 정합니다. 예를 들어 기술 분석가에게 매번 데이터 출처와 기준일을 표시하게 해 보세요.

1. **팀 구성**을 열고 검색창에서 `기술 분석`을 찾습니다. 문서 편집기에 표시되는 경로를 확인하세요. `team/roles/technical-analyst.md`는 역할 지침이고 `team/skills/technical-analyst.md`는 분석 방법입니다.
2. **분석 방법** 문서를 선택하고, 아래 세 줄을 기존 글 끝에 붙여 **변경 내용 저장**을 누릅니다. 저장 전 내용은 따로 복사해 두어도 좋습니다.
3. **리서치 팀**에서 새 질문을 시작하고 담당자에 **기술 분석**을 고릅니다. 저장된 차트를 근거로 연결한 뒤 “이 차트의 최근 추세와 해석이 달라지는 조건을 설명해 줘”라고 요청합니다.
4. 새로 완성된 보고서의 **역할별 근거**에서 출처와 기준일이 들어갔는지 확인하세요. 실행 중이던 분석은 시작할 때 읽은 지침을 계속 사용합니다.

```text
차트 분석 첫머리에 종목명과 티커, 데이터 출처, 봉 주기와 마지막 관측 시각을 적는다.
시각이 제공되지 않으면 ‘자료에 없음’으로 표시한다.
추세에 대한 해석을 한 문장으로 쓰고, 그 해석이 달라질 가격·거래량 조건을 별도 문장에 적는다.
```

팀 구성을 AI와 함께 다듬을 때에는 바꿀 문서를 하나 지정하세요.

```text
내 기술 분석가가 관측값과 해석을 구분해 쓰게 하고 싶어.
아래에 붙인 기존 분석 방법에 추가할 한국어 문장 세 개를 제안해 줘.
각 문장은 결과 보고서에서 적용됐는지 확인할 수 있게 써 줘.
헤드 매니저의 배정과 독립 검토는 지금 흐름을 유지해 줘.
[키·개인 자료를 뺀 기존 분석 방법]
```

**팀 구성 → 직접 편집할 폴더**를 열면 실제 파일 위치가 보입니다. 같은 문서를 편집기로 수정한 경우 앱의 **파일 목록 새로고침**과 **저장된 내용 다시 읽기**로 확인할 수 있습니다. 화면에서 글로 추가한 지침을 실행할 때에는 해당 역할에 연결된 자료·도구·권한이 사용됩니다.

## 소스 복사본을 Codex에 열기

1. 강사가 공유한 GitHub 릴리스에서 `Hyperpass-Research-Web-source.zip`을 받습니다. 원래 앱과 다른 새 폴더에 압축을 전부 푸세요. [배포 파일 목록](https://github.com/rrw9002-ops/Hyperpass-Research-Web/releases)
2. Codex 앱에서 로컬 프로젝트를 열고, 압축을 푼 폴더 중 **`app.py`가 보이는 폴더**를 선택합니다. 같은 위치에 `static/`, `hyperpass/`, `team/`이 있습니다. [OpenAI 데스크톱 앱 안내](https://learn.chatgpt.com/docs/app)
3. 처음이라면 다음 요청부터 보내세요. 이 단계에서 개인 GitHub 저장소를 만들 필요는 없습니다.

```text
이 폴더의 학생용 앱을 수정하려고 합니다. 먼저 README와 실행 방식을 읽고,
차트 화면, 스크리너 데이터, 에이전트 지침에 해당하는 파일을 하나씩 짚어 주세요.
지금은 수정할 파일 후보와 이유만 설명해 주세요.
```

배포된 실행 파일에는 빌드 당시에 묶은 앱 코드가 들어 있습니다. 코드 수정 실습은 복사본의 `app.py`로 실행해야 바뀐 내용을 볼 수 있습니다. 실행 파일 옆 `team/`은 설치 후에도 편집할 수 있는 별도 문서입니다.

## 별도 데이터 폴더로 수정판 실행하기

소스 실습에는 Python 3.11 이상이 필요합니다. `app.py`가 보이는 폴더에서 터미널을 열고 본인 환경의 명령 한 줄을 실행하세요.

Windows PowerShell

```powershell
py -3 -u app.py --port 0 --data-dir ".test-runtime/student-data"
```

Mac 터미널

```sh
python3 -u app.py --port 0 --data-dir ".test-runtime/student-data"
```

`--port 0`은 사용 가능한 로컬 포트를 배정하고, `--data-dir`은 실습용 연구 기록을 따로 보관합니다. 터미널에 표시된 `Hyperpass Research Web` 주소가 수정판입니다. 브라우저가 자동으로 열립니다. 이 실습판의 팀 문서는 방금 압축을 푼 소스의 `team/`에 있습니다. 종료할 때는 해당 터미널에서 `Ctrl+C`를 누르세요.

다음은 작은 수정을 끝까지 맡기는 요청 예시입니다.

```text
이 소스 복사본의 차트 연구실에서 가격 차트의 출처와 마지막 관측 시각을 초보자가 읽기 쉽게 해 줘.
기존 데이터에 관측 시각이 없으면 '시각 미제공'으로 표시해 줘.
팀의 역할과 보고서 흐름, 주문 없는 리서치 범위는 유지해 줘.
실습 데이터 폴더를 사용하고, 수정 후 실제 앱 화면에서 출처가 다른 차트 두 개를 확인해 줘.
어떤 점을 직접 확인했고 어떤 점은 확인할 수 없었는지 알려 줘.
```

작은 변경 하나가 마음에 들면 다음 변경을 요청하세요. 코드 변경 목록을 쉽게 확인하려면 이렇게 요청할 수 있습니다.

```text
이번에 바꾼 파일, 사용자에게 보이는 변화, 확인한 테스트를 각각 짧게 정리해 줘.
수정 전으로 되돌릴 수 있게 변경한 부분만 담은 패치 또는 복사본을 준비해 줘.
개인 기록과 키는 제외해 줘.
```

## 내 GitHub에 보관하거나 새 버전으로 옮기기

내가 수정한 코드의 이력을 남기려면 공개 배포 저장소의 **Fork**로 자신의 작업 저장소를 만들 수 있습니다. 비공개 보관을 원한다면 **새 비공개 저장소**를 만들고 깨끗한 소스 복사본의 코드와 배포 라이선스부터 올리세요. 개인 보고서·실습 데이터·키가 들어간 파일은 올릴 목록에서 제외하세요. 로컬 폴더만 사용해도 모든 수정 실습이 가능합니다.

다음 순서로 백업과 복원을 연습할 수 있습니다.

1. 실험을 마친 뒤 앱을 종료합니다. 실행 창에 `Data:`로 표시된 데이터 폴더와 **팀 구성 → 직접 편집할 폴더**의 `team/`을 함께 복사해 날짜를 붙인 백업 폴더에 보관합니다. 실습 명령을 사용했다면 데이터 폴더는 `.test-runtime/student-data`입니다.
2. 일반 설치의 기본 데이터 위치는 Windows에서 `%LOCALAPPDATA%\HyperpassResearchWeb`, Mac에서 `~/Library/Application Support/HyperpassResearchWeb`입니다. 실행할 때 별도 경로를 지정했다면 실행 창의 경로를 기준으로 찾으세요.
3. 새 배포 ZIP은 새 폴더에 풉니다. 개인화한 역할·스킬만 이전 버전과 비교하고 필요한 문장을 새 `team/` 파일에 옮깁니다. 일반 설치를 같은 사용자 계정에서 같은 데이터 경로로 실행하면 기존 연구 기록을 다시 열 수 있습니다.
4. 잘못 저장한 팀 문서는 앱 편집 화면에서 저장할 때 생성된 `team/.history/`의 이전 문서나 직접 만든 백업에서 내용을 복사해 현재 편집기에 붙여넣고 저장합니다. 연구 기록을 복원할 때에는 앱을 종료한 상태에서 백업을 별도 폴더에 풀고, 소스 실행 명령의 `--data-dir`에 그 경로를 지정해 먼저 내용을 확인하세요.


## 수정을 부탁하고 결과를 확인하는 대화 예시

한 번에 바꿀 내용이 하나면 확인하기 쉽습니다. **요청 → 차이 확인 → 내 PC에서 같은 예로 재현 → 채택 또는 복구** 순서로 진행하세요.

```text
내 개인 복사본에서 기술 분석가만 바꾸고 싶어요. RSI를 해석할 때 사용한 시간 주기와 데이터 출처를 보고서 맨 위에 쓰게 해 주세요. 먼저 현재 지침을 읽고 바뀔 세 줄을 보여 주세요. Head Manager의 배정 방식과 다른 역할은 유지해 주세요.
```

```text
제안한 변경을 개인 복사본에 적용하고 바꾼 파일 경로, 이전 문구, 새 문구를 보여 주세요. 검증하려면 앱을 어디서 열고 어떤 질문을 보내야 하나요? 비용이 드는 실제 AI 호출은 지금 실행하지 말고 내가 직접 할 한 번의 확인 절차를 적어 주세요.
```

```text
검증 결과를 붙입니다: [보고서 첫 부분 또는 오류 문구]. 기대한 것은 [주기와 출처가 첫 단락에 함께 표시됨]입니다. 실제 결과와 다른 부분을 찾아 원인을 알려 주세요. 방금 변경만 되돌리는 방법도 한 단계씩 안내해 주세요.
```

Codex의 권한이나 화면 이름은 버전·언어·계정에 따라 달라질 수 있습니다. 로컬 폴더 접근을 허용할 때는 이번 개인 복사본을 선택합니다. [Codex 공식 빠른 시작](https://developers.openai.com/codex/quickstart)
