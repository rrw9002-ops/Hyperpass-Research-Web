# 검증 범위 — v0.4 / 2026-11-22

이 앱은 매매를 제거한 별도 웹 구현입니다. 원본의 인증 서비스와 동일한 제품이라고

Risk/Judgment의 독립 검토와 역할 책임 분리를 유지합니다.

## 자동 검사

2026-11-22의 최종 소스 검사에서는 `unittest` 173개 중 172개가 통과했고,
Windows 심볼릭 링크 생성 권한에 해당하는 1개를 건너뛰었습니다. 실패는 없습니다.
실제 브라우저에서도 팀 문서 저장·다시 읽기·원문 복원과 저장된 TradingView
41거래 보고서의 표시를 확인했습니다.

Windows Python 3.14에서 자동 검사를 수행했습니다. 주요 검사는 역할 책임 분리,
채택되지 않은 입력 거부, 동일 담당자 수정, 변경된 근거·후보 결론에 대한 재검토,
독립 Risk/Judgment, 호출 한도와 취소, 오류의 데모 전환 금지, API 키 비노출,
CSRF·Origin·Host 검사, 저장·재시작, 반환 종목 일치, 데이터 입력 크기 제한,
TradingView의 로컬 WebSocket 연결 제한 및 배포 시 사용자 데이터 제외입니다.

추가 검사는 여러 제공자의 역할별 모델 선택, 모델별 추론 옵션, 잘못된 모델·추론 설정
거부, Anthropic·Gemini 요청·응답 프로토콜을 포함합니다. 다중 AI 제공자 관련 22개
검사는 모의 응답으로 수행했습니다. 최초 계획에 분석 역할과 독립 검토 역할이 함께
들어오더라도 검토를 현재 근거 채택 이후로 미루는 회귀 검사도 통과했습니다.

진행률은 단계 기준 추정치이며 실행 중 최대 95%, 정상 완료 시에만 100%입니다.
중단·취소·호출 한도 도달은 완료로 바꾸지 않으며 최종 보고서와 중간 기록을 구분합니다.

v0.3 추가 검사는 개별 분석 역할 지정, 차트 계산 14개, Pine 생성 6개,
차트 저장·재조회·내보내기·라이브러리 집계·에이전트 입력 연결 HTTP 검사 6개입니다.
합성 자료를 사용하는 자동 검사는 실제 시장 검증과 구분하며 유료 AI를 호출하지 않습니다.
추가 시작 검사 10개는 포트 자동 선택·명시 포트 유지·권한 오류 구분과 데이터 폴더
중복 실행 잠금을 검증합니다. Windows에서는 실제 파일 잠금과 자식 프로세스의
강제 종료 후 잠금 재획득도 확인했습니다.

v0.4의 TradingView 제어기 검사는 신규 전략 보고서 식별, 이전 보고서 재사용 거부,
거래 0회와 보고서 없음 구분, 컴파일 오류, 원문 백업 후 코드 교체 순서,
백업 저장 실패 시 작업 중단, 비유한 수치의 JSON 처리와 비율 단위를 확인합니다.
추가 Node 검사는 실제 페이지 프로그램을 합성 환경에서 실행해 Pine 코드가 JavaScript로
해석되지 않는지, 저장 확인창을 처리할 때 백업되지 않은 수정분을 버리지 않는지 확인했습니다.
합성 환경 검사는 아래의 실제 TradingView 실행과 구분합니다.

## v0.4 팀 구성

편집 대상은 공통 지침 1개·역할 지침 10개·역할별 분석 방법 10개·공통 참고 문서
12개로 총 33개입니다. 웹 편집기 저장과 `team/` 텍스트 파일 편집을 지원하며,
분석 시작 시 문서 전체 내용과 버전을 복사해 해당 실행에 고정합니다.
진행 중인 분석은 이후 편집의 영향을 받지 않고 다음 실행부터 변경을 반영합니다.

Head Manager와 9개 전문 역할의 식별자·책임 분리·근거 채택·보완·독립 검토 절차는
유지합니다. 임의의 새 역할 추가 UI는 제공하지 않습니다. 편집 기능의 구현과
검사는 사용자가 바꾼 지침으로 실제 유료 AI가 좋은 분석을 완성한다는 증거가 아닙니다.

질문에 첨부하는 흐름, Second Brain의 실제 기록·샘플·미완료 구분을 확인했습니다.
이 화면 확인에서 AI 유료 분석을 시작하지 않았습니다. 연구 기록은 이 앱의 로컬
데이터이며 RUBRIC이나 외부 Notion 전체 자료와 자동 동기화하지 않습니다.

PyInstaller Windows EXE도 격리된 데이터 폴더에서 실행했습니다. 정적 화면 파일,

TradingView 내부 Pine 컴파일을 검증한 것이 아닙니다.
종목·시장·상품·포트폴리오·뉴스·자유질문의 6개 범주, 질문별 모델·추론 강도,

모델 응답은 테스트용 주입 응답입니다. 이 검사는 실제 모델이 일관되게 좋은 투자
판단을 내린다는 증거가 아니며, 유료 API의 실제 호출 성공으로 표시하지 않습니다.

## v0.4 실제 TradingView 실행 — 2026-11-22

Windows의 TradingView Desktop 3.5.0에서 로컬 디버그 연결을 열고,
`KRX_DLY:000660` 표준 일봉 차트로 실행했습니다. Codex MCP를 실행 의존성으로
사용하지 않는 앱의 Python 제어기를 통해 새 문서 생성·코드 입력·컴파일·보고서 수집을
수행했습니다. 기존 강의 전략 2개와 원래 지표를 삭제하거나 덮어쓰지 않았습니다.

이 표의 거래 수와 실행 조건은 **연동 검증 기록**입니다. 검증 전략을 수강생에게 추천하거나
성과의 재현성·통계적 유의성·미래 수익을 입증한 것이 아닙니다. 강의 프리셋을 포함한 모든
Pine 코드·파라미터·종목·요금제 조합의 실제 실행을 확인한 것도 아닙니다.

실제 TradingView 원본 `performance`의 비율은 분수인 반면 앱 표시용 `metrics`는
퍼센트 단위로 변환합니다. 0.4146을 41.46%로 표시하는지 확인했고 원본 값은 유지합니다.
없는 자산곡선은 임의로 계산하지 않습니다. 거래·체결 목록은 최근 500개 한도와 전체
개수를 함께 남기므로 JSON 목록 길이를 전체 거래 수와 혼동하지 않아야 합니다.

Desktop 내부 인터페이스 호환성, 계정의 지표 개수·데이터 범위·계산 제한은 남아 있습니다.
반복 실행은 새 전략을 추가하므로 한도에 도달할 수 있고, 기존 항목을 자동 삭제하지 않습니다.
한 PC의 성공이 모든 수강생 계정·Desktop 버전·OS에서의 성공을 보장하지 않습니다.

## 남아 있는 실제 환경 확인

- OpenAI: 연결 확인과 Head Manager 요청은 실제 성공했습니다. 수정된 앱에서 전문
  분석·채택·독립 검토·최종 보고서까지 이어지는 전체 유료 실행은 추가 확인이 필요합니다.
- Claude·Gemini: 모델 목록·요청 형식·추론 설정·응답 처리는 모의 응답으로 검사했으며,
  실제 계정의 모델 접근 권한과 유료 호출은 미검증입니다.
- KIS·FMP: 위 종목의 실제 조회는 성공했습니다. 다른 학생 계정·요금제·종목에 따른
  조회 권한까지 검증한 것은 아닙니다.
- OpenBB: v4/v5 로컬 API 경로를 구분했습니다. 실행 중인 실제 서버 연결은 미검증.
- TradingView: 위 Windows Desktop의 차트 설정·Pine 컴파일·실제 보고서 수집은
  확인했습니다. Mac Desktop, 다른 계정·요금제, 임의 사용자 Pine 코드의 성공은 미검증입니다.
- Mac: 실행 스크립트·표준 라이브러리 구성은 제공하지만 Mac 기기 실행은 미검증.
- v0.4 Windows 실행 파일: 위 제어기 실측과 최종 배포 패키지 검증을 구분합니다.
  릴리스에 포함된 실행 파일의 검증 기록을 확인해야 합니다. 앞의 v0.3 EXE 확인을
  새 패키지의 검증으로 대신하지 않습니다.

전체 수강생 환경 검증 완료나 안정 버전으로 홍보하기 전에 위 항목을 실제 키와
해당 OS에서 확인해야 합니다. 수강생의 키·로그인 정보는 채팅이나 배포 파일로 받지 않습니다.

최신 소스와 배포 파일은 [공개 저장소](https://github.com/rrw9002-ops/Hyperpass-Research-Web)와
[Releases](https://github.com/rrw9002-ops/Hyperpass-Research-Web/releases)에서 확인합니다.
실측 중 보관한 원본 Pine 코드·연구 기록·개인 설정은 공개 저장소나 배포 ZIP에 포함하지 않습니다.

## API 키 보관과 재시작

AI 제공자별 API 키와 데이터 연결의 비밀값은 실행 중인 서버 메모리에만 보관합니다.
브라우저 저장소·분석 기록·배포 파일에는 저장하지 않습니다. 앱을 완전히 종료하거나
업데이트로 서버를 다시 실행하면 키를 다시 등록해야 합니다. 모델 목록 조회에만 입력한
키는 연결 확인 전까지 등록 상태로 바뀌지 않습니다. 연결 확인은 실제 모델 요청을 사용하며
계정 과금이 발생할 수 있습니다. 모델 목록에 표시된다고 실제 호출 권한까지 보장되지는 않습니다.
