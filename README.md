# Hyperpass Research Web · v0.6.0-preview.1

질문을 입력하면 **Head Manager가 필요한 전문 에이전트를 구성하고, 근거를 검수하고,
보완과 독립 검토를 거쳐 보고서를 남기는 로컬 웹앱**입니다. 브라우저에서 사용하며
Codex 앱·MCP·증권사 인증을 요구하지 않습니다. 매매·계좌 조회·주문 기능은 없습니다.

검정 바탕에 크림색 글자와 주황색 강조를 쓰고, 패널 가장자리에 은은한 유리 반사광을 더했습니다. 저장된 연구는 우주 형태의
지도와 목록에서 살펴볼 수 있습니다. 작업 공간은 다음과 같습니다.

| 공간 | 하는 일 |
| --- | --- |
| 리서치 팀 | 종합 분석 또는 지정한 전문 에이전트에게 질문하고 검토된 보고서 확인 |
| 차트 연구실 | 실제 OHLCV 차트·지표, 로컬 전략 검증, Pine Script 내보내기와 기술 분석 연결 |
| 백테스트 연구실 | 국내·미국 시장, 직접 고른 종목, 단일 종목을 대상으로 전략 검증·저장. TradingView Desktop에서 Pine 전략 실행 |
| Second Brain | 지도를 확대해 저장된 연구 탐색, 관심종목의 시세·연결된 보고서·차트 다시 열기 |
| 팀 구성 | 역할 지침·분석 방법·공통 참고 문서를 편집하고 다음 분석에 적용 |

## 처음 실행

수강생은 [빠른 시작 안내](docs/QUICKSTART.md)를 순서대로 따라 하세요.

1. [v0.6.0 다운로드](https://github.com/rrw9002-ops/Hyperpass-Research-Web/releases/tag/v0.6.0-preview.1)에 게시된
   본인 OS용 ZIP을 받습니다.
   소스 ZIP은 [공개 저장소](https://github.com/rrw9002-ops/Hyperpass-Research-Web)의 **Code → Download ZIP**입니다.
2. ZIP을 **새 폴더에 압축 해제**합니다. 압축 파일 안에서 바로 실행하지 않습니다.
3. 아래 표의 시작 파일을 실행하고, 실행 창을 열어 둔 채 브라우저를 사용합니다.
4. 처음에는 **화면 체험 →**으로 키 없이 화면과 보고서 저장 흐름을 확인합니다.
5. 실제 분석을 하려면 **API 연결하기**에서 사용할 AI 제공자 하나를 연결한 뒤
   질문을 입력하고 **리서치 시작**을 누릅니다. 모든 데이터 제공자를 등록할 필요는 없습니다.
   OpenAI에서는 **검증 설정 적용 · GPT-5.4 / medium** 버튼으로 실제 완주를 확인한
   설정을 선택할 수 있습니다. 버튼 자체는 분석을 시작하거나 API 비용을 발생시키지 않습니다.

| 환경 | 실행 방법 |
| --- | --- |
| Windows 실행 파일 배포본 | ZIP 안의 `Hyperpass-Research-Web.exe`를 더블클릭합니다. Python 설치가 필요 없습니다. `Start-Windows.cmd`도 같은 EXE를 실행합니다. |
| Mac 실행 파일 배포본 | Apple Silicon(M 시리즈)은 `macOS-arm64`, Intel은 `macOS-x86_64` ZIP을 선택하고 `Start-Mac.command`를 엽니다. 포함된 실행 파일을 사용하므로 Python 설치가 필요 없습니다. |
| Windows 소스 배포본 | Python 3.11 이상을 설치한 뒤 `Start-Windows.cmd`를 엽니다. |
| Mac 소스 배포본 | Python 3.11 이상을 설치한 뒤 `Start-Mac.command`를 엽니다. 실행 권한 때문에 열리지 않으면 아래 수동 실행을 사용합니다. |

이 버전은 사전 검증용입니다. Windows x64·Mac Apple Silicon·Mac Intel을 각각
네이티브 빌드하고 소스·단독 실행 파일·ZIP 설치를 검사하는 CI를 사용합니다.
게시된 파일의 동일 커밋 통과 기록은 릴리스에 첨부한 검증 JSON에서 확인하세요.
실제 사용자 Mac의 GUI 실행, 다운로드 후 Gatekeeper 동작과 Mac TradingView 연동은 미검증입니다.
Mac 실행 파일은 Apple 개발자 서명·공증을 제공하지 않습니다.
실제 AI는 `gpt-5.4`·추론 `medium`로 기술 분석 → 근거 채택 → 독립 검토 → 최종 보고서 완료를 확인했습니다.
다른 모델·계정의 성공을 같은 결과로 보지 않습니다. 새 배포 파일의 CI 결과와 SHA-256은 릴리스의 검증 JSON을 확인하세요.

소스 배포본은 **Python 3.11 이상**이 한 번 설치되어 있어야 합니다.
[공식 Python 설치 파일](https://www.python.org/downloads/)을 사용하세요.
Windows 설치 화면에서는 `Add python.exe to PATH`를 선택하면 편합니다.
Python 설치 후에는 pip·npm·Django·추가 패키지를 설치할 필요가 없습니다.

실행 창을 열어 둔 상태에서 창에 표시된 URL을 사용합니다. 보통 `http://127.0.0.1:8765`이며, 사용 중이면 다음 로컬 포트를 자동으로 선택합니다.
브라우저가 자동으로 열리지 않으면 이 주소를 직접 여세요. 앱을 완전히 종료하려면
실행 창에서 `Ctrl+C`를 누릅니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.
같은 데이터 폴더로 앱을 다시 실행하면 새 서버를 만들지 않고 기존 앱 주소를 안내합니다.
기존 앱이 강제로 종료되더라도 운영체제가 실행 잠금을 해제하므로 다시 실행할 수 있습니다.

## 키 연결과 분석

1. 웹앱의 **AI 연결**에서 OpenAI·Claude(Anthropic)·Gemini 중 사용할 제공자를
   선택하고 본인의 API 키를 입력합니다. **모델 목록 불러오기**로 계정에서 제공되는
   모델을 조회한 뒤 연결을 확인합니다. 사용할 제공자만 등록하면 됩니다.
2. **누구에게 물어볼까요?**는 기본적으로 **종합 분석**입니다. 필요하면 기본·기술·뉴스·
   매크로·상품·가치 평가·포트폴리오 중 담당 에이전트를 지정합니다. 질문 범주는
   **종목 / 시장·거시 / ETF·상품 / 포트폴리오 / 뉴스·이벤트 / 자유질문** 중에서 고릅니다.
   분석 대상·시장·기간·원하는 결과를 각각 선택하던 네 입력칸은 없앴습니다.
   필요한 조건을 질문에 자유롭게 적거나 범주의 예시 질문을 사용할 수 있습니다.
3. 질문마다 **AI 제공자 → 모델 → 추론 강도**를 선택합니다. 추론 강도에는 선택한
   모델이 지원하는 옵션만 표시됩니다. Codex 앱의 Astra·Ultra 표시와 API 모델 이름은
   서로 다르므로 동일한 이름이나 단계로 자동 대응하지 않습니다.
4. 필요한 데이터 연결·저장된 차트 결과를 선택하거나 참고 자료를 넣습니다. 지원하는 모델의 웹 검색도
   선택할 수 있습니다. 데이터·참고 자료·웹 검색이 모두 없으면 시작 전에 안내합니다.
5. 분석을 시작하고 진행 상태와 각 역할의 근거를 확인합니다. **최종 보고서 완성**으로
   표시된 결과를 확인하고 Markdown으로 내려받습니다.

개별 에이전트를 지정하면 해당 역할이 근거를 생산하고, Head Manager가 검수·보완을
관리합니다. Risk·Judgment는 독립 검토 단계에 참여하며 첫 분석 담당자로 직접
선택하지 않습니다. 개별 분석도 필요한 검토를 거치므로 모델 요청 한 번으로 끝나는
단일 답변 방식은 아닙니다.

**역할별 모델 설정**에서는 제공자·모델·추론 강도를 다르게 지정할 수 있습니다.
담당 역할 선택과 담당 AI 설정은 별개입니다. 모델을 배정했다고 해당 역할을 추가로
강제 호출하지 않으며, 종합 분석의 최소 팀 선택과 근거 채택·보완·독립 검토 원칙은
그대로 유지됩니다.

실제 AI 분석에는 선택한 제공자의 API 키가 필요합니다. KIS 데이터를 선택할 때만
데이터 연결 화면에 본인 App Key·Secret을 입력합니다. 계좌번호나 매매 권한은
사용하지 않으며, KIS 연결도 시세 조회로 제한됩니다.
키는 브라우저 저장소나 보고서에 저장하지 않고 실행 중인 로컬 서버 메모리에만
보관합니다. 서버를 다시 실행하면 다시 연결해야 합니다. 로컬 메모리 보관이
같은 컴퓨터의 다른 프로그램으로부터 완전한 비밀 보호를 보장하는 것은 아닙니다.

API 연결 확인도 실제 API 요청이며, 실제 분석은 사용하는 계정의 API 한도와 과금
조건을 따릅니다. ChatGPT/Codex·Claude·Gemini 앱 로그인이나 구독만으로 이 앱의 API
인증을 대신하지 않습니다.
사용 가능한 모델·잔액·조직 권한을 확인하세요. 요청 횟수 제한은 과도한 반복을
줄이는 장치이며 금액 한도가 아닙니다. 웹 검색 사용 여부와 출력 길이에 따라
비용이 달라집니다. 분석 중지 시 이미 전송된 API 요청의 비용은 취소되지 않습니다.

질문·입력한 자료·선택한 맥락은 해당 역할에 지정한 AI 제공자로 전송됩니다.
여러 제공자를 섞으면 채택된 근거가 다른 역할의 제공자에게도 전달될 수 있습니다. API 키를 참고
자료에 붙여넣지 마세요. 외부 웹 검색을 켜면 모델이 검색한 출처를 사용하며,
최신 금융 데이터나 유료 데이터 접근이 항상 보장되는 것은 아닙니다.

## 진행률과 보고서 상태 읽기

상단 배너에 현재 단계·담당 역할·진행률이 표시됩니다. 진행률은 **단계 기준 추정치**로,
남은 시간이나 투자 판단의 신뢰도가 아닙니다. 실행 중에는 줄어들지 않으며 최대 95%입니다.
근거 보완이나 재검토가 필요하면 같은 퍼센트에서 작업이 이어질 수 있습니다.

| 표시 | 의미 |
| --- | --- |
| 분석 진행 중 | 계획·자료 수집·근거 검수·보완·독립 검토 중. 최종 보고서가 아직 없음 |
| 최종 보고서 완성 · 100% | 최종 보고서가 저장된 정상 완료 |
| 분석 중단 · 최종 보고서 없음 | 오류나 근거 부족으로 종료. 원인을 확인한 뒤 다시 시작해야 함 |
| 호출 한도 도달 / 사용자 중지 | 해당 실행이 종료됨. 중간 기록은 볼 수 있지만 최종 보고서 완성은 아님 |

중단·한도 도달·사용자 중지는 100%로 표시하지 않습니다. 진행 정보가 없던 과거 기록은
임의의 퍼센트를 만들지 않습니다. **중간 기록**과 **최종 보고서**를 구분해서 확인하세요.

## 키 없이 화면을 살펴보기

**화면 체험(샘플)**은 고정된 가상 사례를 재생합니다. 실제 AI 분석이나 실시간
시세 조회가 아니며 API 키·네트워크가 필요 없습니다. 실제 연결이 실패했을 때
샘플을 실제 결과처럼 대신 보여주지 않습니다.

## 차트 연구실 사용

1. 상단 **차트 연구실**에서 Yahoo Finance, TradingView의 열린 Desktop 차트,
   TradingView에서 내보낸 CSV 중 데이터 출처를 선택합니다.
2. 종목과 기간·주기를 확인합니다. Desktop 연결은 TradingView에서 미리 열린 종목과
   주기를 읽습니다. 먼저 웹앱의 **TradingView** 탭에서 설정할 수도 있습니다. 현재가 한 개만 있는 시세는
   과거 OHLCV를 대신할 수 없습니다.
3. **강의 ① 추세 돌파**, **강의 ② 평균 회귀**, 추가 SMA 교차 예제 또는
   **지표·차트만 분석**을 선택하고 **차트 불러오기 · 전략 검증**을 누릅니다.
4. 캔들·거래량과 SMA·EMA·Bollinger, RSI·MACD·ATR를 살펴봅니다. 비용과 검증 기간을
   조정했다면 다른 실험으로 계산하고, 성과·자산 곡선·후반 검증 구간·비용 민감도를 확인합니다.
5. 계산 결과는 Second Brain에 저장됩니다. 원본 결과 JSON과 Pine Script를
   내려받거나 **기술 분석 에이전트에게 질문**으로 계산 근거를 연결할 수 있습니다.

조회·지표·백테스트 계산에는 AI 키가 필요하지 않습니다. AI 해석은 질문을 확인하고
리서치를 시작할 때 해당 제공자의 API로 실행합니다. 차트 결과를 연결하면 기술 분석
담당자가 선택되고, 저장된 계산 결과와 한계를 근거로 전달합니다.

이 탭의 백테스트는 **로컬 OHLC 계산**입니다. 신호 이후 다음 관측 시가 체결, 수수료·슬리피지,
미청산 포지션 평가 등을 명시하며 TradingView Strategy Tester와 같은 결과라고
표시하지 않습니다. TradingView에서 직접 실행할 때는 아래의 별도 탭을 사용합니다.

Pine 내보내기는 표준 일봉용 텍스트입니다. 로컬 슬리피지가 bps이면 내보내기에서는
강의 가정인 1틱으로 바뀌므로 코드와 비용·날짜 설정을 확인해야 합니다.
원본 강의 출처와 계산·체결 차이는 [차트 Lab 안내](docs/CHART-LAB.md)에 있습니다.

## TradingView에서 실제 백테스트 실행

1. **TradingView Desktop을 설치하고 본인 계정으로 로그인**한 뒤 차트를 엽니다.
   웹앱의 **TradingView → Desktop 연결 실행**을 누르고 **연결 확인**으로 현재
   종목·주기가 보이는지 확인합니다. 기본 연결 포트는 9222입니다. 이미 실행 중인
   앱에 디버그 연결이 없으면 안내에 따라 직접 종료 후 다시 연결 실행하세요.
2. 차트가 여러 개라면 작업할 창을 선택합니다. 종목명이나 티커를 입력합니다.
   예를 들어 `삼성전자`, `엔비디아`, `NVDA`로 검색한 뒤 목록에서 거래소와 종목을
   확인해 선택합니다. 주기와 기본 지표를 정하고 **차트 설정 적용**을 누릅니다.
3. `strategy()`로 선언한 Pine 코드를 붙여넣거나 **Pine 파일 읽기**로 불러옵니다.
   차트 연구실에서 내보낸 Pine도 사용할 수 있습니다. 코드를 확인한 뒤
   **전략 적용 · 백테스트**를 누릅니다.
4. 앱이 기존 편집기 코드를 백업하고 새 전략 문서를 만든 뒤 TradingView에서
   컴파일합니다. **이번 실행으로 새로 추가된 전략의 실제 보고서**가 확인되어야
   완료됩니다. 컴파일 오류·대기 시간 초과·보고서 없음은 미완료로 남습니다.
5. 결과와 실행 기록을 확인하고 **실행 결과 JSON**을 내려받습니다. **실행 전 Pine 코드**로
   이전 원문을 내려받아 필요할 때 편집기에 다시 붙여넣을 수 있습니다. 완료된 결과는 **기술 분석 에이전트에게 질문**에
   연결할 수 있으며, AI 해석을 시작할 때만 별도의 AI API 키를 사용합니다.

반복 실행 시 저장 확인창이 뜨면, 백업한 내용과 현재 편집기 내용이 같은 경우에만
저장하지 않고 새 문서로 넘어갑니다. 기존 저장 스크립트를 덮어쓰거나 퍼블리시하지 않습니다.
새 전략·지표는 차트에 추가되며 기존 항목을 자동 삭제하지 않으므로 계정의 지표 개수
한도에 도달할 수 있습니다. 필요 없는 실험은 사용자가 TradingView에서 정리하세요.

TradingView API 키는 필요하지 않습니다. **Desktop 설치·로그인·로컬 디버그 연결**과
해당 계정의 데이터·기능 이용 권한은 필요합니다. 요금제에 따라 지표 수·과거 데이터·
계산 제한이 달라지며 앱이 이를 해제하지 않습니다. [공식 요금제 비교](https://www.tradingview.com/pricing/)
및 [전략 데이터 범위 안내](https://www.tradingview.com/pine-script-docs/faq/strategies/)를 확인하세요.
Windows Desktop에서 실제 컴파일·보고서 수집을 확인했으며 Mac의 동일 동작은 아직 미검증입니다.

## 차트에 나만의 지표 그리기

TradingView 탭에서 최근 1년 고점 연결 예제를 열어 코드를 확인하고 차트에 적용합니다.
다른 아이디어는 원하는 선·계산 기준·기간을 한국어로 적고 연결한 AI로 코드를 생성합니다.
직접 작성한 Pine `indicator()` 코드도 붙여넣을 수 있습니다. 코드를 편집하고 이름을
붙여 저장하면 이 컴퓨터에서 다시 열어 수정할 수 있습니다. 차트에 적용한 뒤 실행 결과를 확인하세요.
전략 백테스트에는 별도의 `strategy()` 편집 영역을 사용합니다.

## 팀 지침과 분석 방법 수정

**팀 구성**에서 문서를 선택해 수정하고 **변경 내용 저장**을 누릅니다. 편집 가능한 문서는
공통 지침 1개, Head Manager를 포함한 역할 지침 10개, 역할별 분석 방법 10개,
공통 참고 문서 12개로 **총 33개**입니다. 화면에 표시된 `team/` 폴더의 텍스트 파일을
편집기로 직접 수정할 수도 있습니다.

저장한 내용은 **다음에 시작하는 분석부터 적용**됩니다. 실행할 때 문서 전체의 내용과
버전을 복사해 보관하므로, 진행 중에 지침을 고쳐도 이미 시작한 분석의 기준은 바뀌지
않습니다. 다른 창에서 같은 문서를 먼저 수정했다면 최신 내용을 다시 읽어야 저장할 수 있습니다.

역할의 설명·분석 방법은 바꿀 수 있지만 새로운 역할을 자유롭게 추가하는 화면은 없습니다.
원본의 Head Manager와 9개 전문 역할, 최소 팀 선택·근거 채택·보완·독립 검토의 책임
구조를 유지하기 위한 범위입니다. 지침 편집과 역할별 AI 모델·추론 강도 설정은 별개입니다.

## Second Brain 사용

**Second Brain**에서 보고서·차트·미완료 기록·샘플을 구분하고 제목·표시 요약·범주·
담당 역할로 검색합니다. 기록을 열면 저장 당시 결과를 다시 볼 수 있습니다.
완료된 실제 연구의 **이전 판단으로 사용**을 선택하면 질문의 참고 기억에 연결됩니다.
미완료 기록이나 고정 샘플을 완료된 실제 연구로 재사용하지 않습니다.

우주 형태의 지도와 기록 수는 이 앱에 저장된 최근 기록을 바탕으로 표시합니다.
다른 프로젝트·Notion·외부 Second Brain과 자동 동기화하거나 모델을 자동 학습시키는
기능은 아닙니다. 이전 보고서를 선택해 연결해도 새 자료와 구분해 검토하며,
과거 결론이 현재의 근거를 자동으로 대신하지 않습니다.

## 선택 데이터 연결

| 연결 | 필요한 설정 | 제공 범위·한계 |
| --- | --- | --- |
| 한국투자증권 KIS | App Key·App Secret | 6자리 국내주식 종목 현재가. 토큰 발급과 시세 조회만 사용하며 계좌·주문은 호출하지 않음 |
| FMP | FMP API 키 | 주식 시세. 가입 상품과 종목 이용 권한에 따름 |
| Yahoo | 키 없음 | 공개 가격 이력. 차트 연구실에서는 1·2·5년과 일·주·월봉 선택. 비공식 경로라 변경·차단될 수 있음 |
| TradingView | Desktop 설치·로그인·로컬 연결 / 공개 조회 / CSV | 데이터 연결은 열린 차트 OHLCV·표시 지표, 공개 스크리너, CSV를 지원합니다. 실제 차트 설정과 Pine 실행은 별도 **TradingView** 탭에서 합니다. [차트 Lab 안내](docs/CHART-LAB.md) |
| OpenBB | 로컬 서버 포트·버전, 필요한 경우 사용자명·비밀번호 | 같은 컴퓨터의 OpenBB API에 연결. v5는 CBOE quote, v4는 yfinance historical 경로. OpenBB 서버·provider는 별도 설치 필요 |

데이터 연결에서 **실제 조회로 연결 확인**을 눌러 성공해야 **조회 확인됨**으로 표시되고
분석에 선택할 수 있습니다. 연결에 성공했더라도 이후 조회는 서비스 상태와 이용 한도에 따라 실패할 수 있습니다.
조회 시각과 데이터 기준 시각은 구분해서 기록합니다. 제공자가 기준 시각을 주지
않으면 `unknown`으로 남깁니다. 모든 데이터 연결의 비밀값도 서버 메모리에서만
유지하며 서버 종료 시 다시 입력해야 합니다.

TradingView에는 일반 사용자용 공식 시세 API가 없다는 [공식 안내](https://www.tradingview.com/support/solutions/43000474413-i-need-access-to-your-api-in-order-to-get-data-or-indicator-values/)가
있습니다. 이 앱의 공개 스캐너를 공식 지원 API로 이해하면 안 됩니다.
데이터 연결의 CSV는 `time` 또는 `date`, `close` 열이 필요하며 최대 1,000행을 받습니다.
차트 연구실의 CSV는 OHLC가 모두 필요하고 최대 5,000행을 받습니다.
기간·시간대·배당 조정 기준은 원본 내보내기 설정을 확인하세요.

OpenBB v5 경로·로컬 포트·인증 방식은 [공식 REST 문서](https://docs.openbb.co/odp/python/quickstart/rest_api)에
따릅니다. 임의 외부 서버 주소와 다른 주소로의 리디렉션은 허용하지 않습니다.

## 저장과 백업

보고서·차트 실험·TradingView 실행 기록과 분석 시작 당시의 지침 사본은 사용자 앱
데이터 폴더에 저장됩니다. 정확한 경로는 실행 창의 `Data:` 안내를 확인하세요.
프로그램을 새 폴더에 설치해도 기존 연구 기록은 별도로 남습니다.
업데이트한 앱을 열기 전에는 이전 실행 창에서 `Ctrl+C`로 종료하세요. 이전 앱이
열려 있으면 새 실행도 기존 앱 주소를 안내하므로 새 버전으로 전환되지 않습니다.

직접 편집하는 현재 지침은 **실행 파일 옆 `team/` 폴더**에 저장됩니다. 소스 실행에서는
`app.py` 옆 `team/`입니다. 화면의 **팀 구성**에도 정확한 경로가 표시됩니다.
새 폴더에 압축을 풀면 기본 지침으로 시작하므로, 기존 편집 내용을 유지하려면 이전
`team/`을 별도로 백업하고 새 버전의 문서와 비교해 옮기세요.
보고서 Markdown, 차트·TradingView 결과 JSON, 실행 전 Pine 코드도 필요에 따라 내보낼 수 있습니다.
학생의 키나 분석 결과가 포함된 사용자 데이터 폴더를 재배포하지 마세요.

## 수동 실행·문제 해결

터미널에서 압축을 푼 프로젝트 폴더로 이동한 뒤 실행합니다.

```text
# Windows
py -3 app.py

# Mac
python3 app.py
```

기본 실행은 8765부터 사용 가능한 로컬 포트를 자동으로 선택합니다.
특정 포트를 쓰려는 경우에만 `--port 8766`을 붙입니다. 명시한 포트가 사용 중이면 다른 포트로 바꾸거나 옵션을 생략하세요.
브라우저 자동 열기가 필요 없으면 `--no-browser`를 붙입니다.
Mac에서 실행 권한만 없는 경우 `chmod +x Start-Mac.command`를 실행할 수 있습니다.
관리자 권한, 보안 설정 해제, 기존 Codex 설정 삭제는 필요하지 않습니다.

API 오류가 나면 웹앱에서 연결을 다시 확인하세요. 인증 실패, 사용량 한도,
모델 접근 권한, 네트워크 오류는 서로 다른 문제입니다. 오류 상태를 성공으로
표시하지 않습니다. 중간 근거가 충분하지 않거나 호출 한도에 도달하면 보고서는
완료 대신 차단·미완료 상태를 남길 수 있습니다.

## 배포와 검증

[v0.6.0 릴리스](https://github.com/rrw9002-ops/Hyperpass-Research-Web/releases/tag/v0.6.0-preview.1)의 검증 파일에서 배포 커밋, OS별 테스트와 설치 점검, ZIP의 SHA-256을 확인할 수 있습니다.
설치 점검에는 실제 앱을 실행해 개인 지표를 저장하고 수정한 뒤 다시 여는 과정이 포함됩니다.

[v0.4.1 검증 기록](docs/VALIDATION.md)에는 Windows에서 OpenAI `gpt-5.4`·추론 `medium`으로 실제 TradingView 백테스트를 해석해 독립 검토와 최종 보고서 내보내기까지 완료한 결과가 있습니다.
Windows에서 Yahoo·TradingView·KIS·FMP 데이터 조회도 확인했습니다. Claude·Gemini 유료 계정, 실제 사용자 Mac의 GUI·Gatekeeper·TradingView는 별도 확인이 필요합니다.
차트 연구실의 계산 검사는 모의 OHLCV와 실제 Yahoo AAPL·하이닉스 이력으로
수행했습니다. 별도로 Windows TradingView Desktop에서 새 Pine 전략 컴파일·실제
41거래 보고서 수집·SMA20/RSI14 추가·반복 실행·컴파일 실패 처리를 확인했으며,
웹앱의 HTTP 요청부터 실제 백테스트 보고서 저장까지 이어지는 경로도 성공했습니다.
이 결과는 연동 동작의 확인이며 전략의 수익성이나 임의의 Pine 코드 전체를 검증한
것은 아닙니다. Pine 내보내기만으로 실행 성공을 뜻하지는 않습니다.
[검증 범위](docs/VALIDATION.md)를 확인하세요. 유지보수 명령은 다음과 같습니다.

```text
python -m unittest discover -s tests -v
python tools/build_release.py
```

두 번째 명령은 허용된 소스·정적 파일만 모아 `dist/`에 ZIP과 SHA-256 파일을
생성합니다. 키용 환경 파일, 연구 기록, 데이터베이스, 캐시, 지침 편집 이력은 포함하지 않습니다.
현재 `team/`의 고정 33개 문서는 포함하므로 개인 지침이 없는 깨끗한 배포용 체크아웃에서 실행하세요.
프로젝트 폴더 전체를 임의로 압축하지 마세요.

Windows·Mac 실행 파일 제작과 OS별 검증 방법은 [배포 안내](docs/DISTRIBUTION.md)를 참고하세요.
