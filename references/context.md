# Context, memory and explicit authoring

Keep five distinct forms of memory. Existing records may be read when relevant;
new Wiki, Brain, Strategy or investor-context writes require the user's explicit
request. Completing research is not permission to rewrite a method or instructions.

| Layer | Location | Meaning |
| --- | --- | --- |
| Research | `trading/runs/` | Current sources, data, calculations and accepted reports |
| Wiki | `wikis/` | Reusable background; recheck time-sensitive facts |
| Investment Brain | `investment-brains/` | Inquiry principles, causal frames, falsifiers, limits |
| Strategy | `strategies/` | User-owned decision rules, with no execution authority |
| Decision Memory | `trading/decisions/` | Prior judgments, outcomes, postmortems and candidate lessons |

User-confirmed suitability context lives in `context/investor-context.md`.
Do not infer holdings, assets, cash or risk tolerance. Portfolio review uses
explicitly supplied, dated holdings; this edition does not read broker accounts.

At most one explicitly chosen Brain and one Strategy apply to a run. Copy their
exact version/path and computed hash when available into the mandate. Don't
blend frameworks. A missing/changed selected overlay is `waiting`, not permission
to simulate it. Brain shapes inquiry but never picks agents, tools or schedules.
Strategy determines decision rules; current evidence controls whether the factual
conditions hold. Preserve any conflict instead of hiding it.

For a new judgment, save the independent current view before reading relevant
prior decision outcomes to reduce anchoring. Explain any post-memory change.
Historical replay uses only evidence available at that cutoff, with restatements
and hindsight separated. Record outcomes against the original horizon and
resolution source; distinguish process quality from lucky/unlucky results.

Lessons remain proposals until explicitly adopted. No self-training claim or
silent changes to AGENTS, roles, skills, policy or permissions. Repeated patterns
need supporting cases and counterexamples, not just one successful forecast.

Recurring research uses the host's native scheduling capability only when the
user requests it. Check that the scheduled run can open this project and load
these roles; never claim a schedule exists without an actual creation result.
No cron/daemon/service is bundled. All scheduled work remains research-only.
